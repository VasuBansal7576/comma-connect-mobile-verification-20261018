# Comma Connect mobile verification lab

Free, bounded verification helpers for the public Comma Connect candidate test lab. Current product build: V15. This repository contains test-only code and generated fixture definitions; it contains no account credentials.

The first manual workflow inventories a fresh GitHub macOS runner, checks existing screen-capture permission without requesting or changing it, then calibrates digital system-audio capture with a native 440 Hz / silence / 440 Hz WAV. Audio generation refuses to run outside the remote GitHub macOS job. Nothing plays on the user’s Mac. It installs no SDKs or drivers, accepts no license agreements and does not change privacy settings.

A passing calibration establishes the capture path only. It does not verify an iPhone, installed PWA, physical speakers or either product issue. Results are retained as short-lived workflow artifacts. The product test lab is https://comma-connect-fix-lab-20261016.zippy17.chatgpt.site/v15/menu.

The installed-PWA feasibility workflow uses only preinstalled iOS runtimes and Xcode. It adds the owned fixture to Home Screen through actual Safari UI, launches the icon and checks both standalone flags. It captures the remote simulator’s digital output while the test taps playback controls. No HAL driver or extra SDK is installed. Simulator results remain distinct from physical iPhone results and from actual product verification.

The consolidated V15 native workflow shares one boot, build and real Home installation across playback, URL and audio cases. Each case navigates through the installed WebClip's real menu to its intended document. The standalone audio workflow remains available for a focused run; both are manual. Fixed command deadlines include bounded cleanup and retain receipts separately from optional raw Xcode bundles. The audio capture remains 150 seconds after actual native READY, with an unchanged 130-second active protocol limit. Source/carrier hashes, actual standalone flags, transport branch, controls and numeric output must still be assessed from the retained artifacts. A skipped native-HTTP branch does not verify that branch. HTTP-client failures remain separate from the mandatory stock-browser byte gate.

Hosted Android prerequisite checks use an ephemeral VM, exact stable packages whose licenses the runner already accepts, and an isolated silent audio sink. They accept no new SDK agreements. A separate default-off input requires explicit human approval for the exact Chrome 124 welcome Terms/data-reporting disclosure and one "Use without an account" click, then captures and stops. It adds no account. A green first-screen job can explicitly end with `UNKNOWN` or `REQUIRES_REVIEW`: it does not mean installation, PWA behavior or audio passed. No Android SDK or emulator is installed on the user's Mac. Any future audio test must enable the emulator's output and verify its private sink routing; the initial `-no-audio` boot checks provide no audio evidence.
